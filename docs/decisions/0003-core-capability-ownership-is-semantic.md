# 0003 · 核心能力归属由权威语义决定

- 状态：accepted
- 日期：2026-07-18
- 关联条款：MOB-001、GOV-001～GOV-005

## 背景


## 决定

能力归属按权威状态和跨客户端语义决定，不按需求最先由哪个客户端提出决定。

2. Akashic 专属客户端体验仍由客户端拥有；核心只提供已经批准的中立能力。
3. session、turn、ack、resume、取消终态和附件传输确认等需要服务端权威状态或跨客户端一致语义的能力，可以由核心或中立协议拥有。
4. 修改核心 runtime 前必须说明现有不变量、权威 owner、客户端替代方案为什么不成立，以及新增接口如何保持 transport-neutral。

## 理由

平台共性不等于服务端权威语义。把平台能力留在客户端，可以避免核心依赖移动操作系统；把真正的权威状态留在核心或协议，可以避免多个客户端分别猜测恢复、幂等和终态规则。

## 影响

- 跨仓库任务合同和 PR 必须声明能力 owner、消费者范围和 runtime patch 理由。
- Stacked PR 评审先检查每层 `base..head` 的 owner，再检查最终 head 的累计行为。
- 客户端仓库可以固定核心协议快照，但不能通过修改快照反向定义核心语义。
- 核心确需补能力时，先批准协议或不变量，再修改 runtime 和跨仓库验收。

## 验收

- Review 能明确区分客户端实现、协议快照和核心权威实现。
